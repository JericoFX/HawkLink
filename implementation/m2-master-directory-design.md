# M2 — primera capa del directorio

Alcance actual: catálogo inmutable en memoria y respuestas HTTP de sólo lectura. MasterDirectory recibe únicamente metadatos de servidores. Ningún campo de su modelo guarda SteamID, cuentas, grants, sesiones, inventarios, saldo o XP. Registro remoto, heartbeat/leases, persistencia del directorio, sincronización entre Masters y ejecutable de despliegue quedan en la fase operativa; no se atribuye este snapshot a un Master completo.

Se proyectan los metadatos sobre el listing Meteor recuperado. Users/AllowedRoles están vacíos y DeveloperData es un objeto vacío; no se fabrican identificadores de jugadores para simular ocupación. La región se declara en el catálogo; no se deduce de IP ni se sondea ningún host.

El consumer check confirmó dos límites: EXE SHA4a861ecb4ac7add9554f8daf8f98ad2c12b9cb6c1865a83e8be808beb46ea8a2, RVA0xbd0810/raw0xbcfc10 calcula slots libres como MaxUsers menos NumMeteorIds(Users); RVA0xbe44e0/raw0xbe38e0 compara Users con una identidad local y después pide ClientSession. Evidencia implementation/evidence/m1-server-viability/m1-users-projection.json y fuente Ghidra identificada allí. Por tanto Users vacío representa0 ocupados y no cumple la rama de membership para asignación. No demuestra admisión ni justifica simular IDs. La fachada del servidor debe construir el listing/sesión con su estado local; este directorio snapshot no se acepta como browser live de partidas ocupadas. No hay campo wire independiente de ocupación confirmado.

Contratos estáticos: SDK original SHA-256 f63fef02ffb517ca7844a769d03412ad82bd22198397302ee3c090c63a970c57, parser RVA0x7a610/raw0x79a10, requests colección RVA0x7f0d0→0x7e7e0 y por-ID0x7de00→0x7d580; helper escape0xf0680; envelope0x708a0; predicado éxito0x26130. Evidencia en research/2026-10-10 y implementation/evidence/m2-sdk-results. Status200, Message string, Result array en colección/object por ID, Port string. Sólo GET /gameServerListings y /gameServerListings/{id}; cinco filtros Region, GameVersion, Map, GameType, ServerName. Login/perfil/inventario/userGameServers/session pertenecen a la API del servidor elegido y no se exponen aquí.

Políticas propias explícitas, no hechos atribuidos al servicio original: filtros por igualdad exacta y conjuntiva, vacíos ignorados, keys duplicadas/desconocidas inválidas, decoding percent una sola vez; plus literal (el SDK escapa el plus como %2B). IDs opacos ASCII URL-safe hasta128 bytes, metadatos de texto UTF8 sin controles hasta256 bytes, destinos IPv4 literales y puertos no cero, capacidad positiva; snapshots sin IDs duplicados. Esta restricción IPv4 sigue el socket de juego recuperado; no se promete soporte IPv6/DNS. Target máximo4096 bytes. Respuestas de error sanitizadas, sin eco del target/body/cabeceras. Sin logger de requests ni datos de jugadores.

Integración usa cpp-httplib0.58.0 fijado en third_party, sobre loopback efímero sólo en pruebas. No acredita interoperabilidad con Hawken original, HTTPS de producción ni red pública. El cliente sigue sin modificar y MeteorUri continúa bloqueado por la sobrescritura estática hasta comprobar la integración nativa.

Política de recursos propia añadida tras revisión: máximo1000 metadatos por snapshot, comprobado antes de validar registros. No es un límite inferido del original. HTTP fija2s de lectura/escritura y payload8192; aún necesita un ejecutable con bind/TLS y límites de conexiones, cola y tasa antes de exposición pública.

Diez casos independientes verificados después de RED: esquema/proyección sin datos privados, directorio vacío/visibilidad, filtros/codificación UTF8, ID/endpoint exclusivo, inputs ambiguos/redacción, validación del catálogo,1000/1001 registros y dos pruebas HTTP loopback. Gate `implementation/evidence/m2-cpp-final-green`:10/10 casos y170/170 aserciones; configure/build/CTest0. El cliente httplib del fixture desactiva path_encode para enviar los bytes percent-escaped del SDK; raw+ sigue siendo literal en el servidor. No se debilitó esa política para acomodar el cliente del fixture.

Build/tests son exclusivos de Luna, aceptación del padre. La aceptación es de formato/filtros/HTTP local y no de un Master completo, browser live, TLS, Steam o partida. La comprobación ASan sigue fallando por el caso de destrucción global descrito en la auditoría; no se declara PASS instrumentado.
